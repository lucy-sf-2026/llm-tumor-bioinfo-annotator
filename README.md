## 📌 项目简介

肿瘤多组学生信分析在完成差异分析后，往往会批量产出几十到上百个候选基因。传统流程中，研究者需要逐个检索 PubMed 与各类生物数据库、人工研读文献并整理基因—疾病关联证据，**重复性高、耗时长，且容易遗漏关键临床证据**。

现有生信平台大多只做通路富集，缺少配套的定向文献挖掘；通用大模型虽能总结文献，却普遍存在 **幻觉、溯源缺失、难以对接权威生物数据库** 等问题。

本工具将 **公共数据库查询、定向文献检索、大模型受约束摘要** 整合为一条可溯源流水线：

- 输入：一份基因列表（CSV）
- 输出：功能富集结果 + 结构化文献证据汇总 + 可视化报告
- 关键约束：**所有结论仅基于抓取到的 PubMed 摘要生成，并强制绑定 PMID 文献编号**，最大限度规避无依据推断

> ⚠️ 当前以**肿瘤基因集**作为验证场景，架构已解耦，可拓展至生命科学其他研究方向。全程无需湿实验。

## 🏗️ 技术方案 / 系统架构

```
用户上传基因列表 (CSV)
        │
        ▼
┌───────────────────┐
│  数据接口层         │  Entrez / STRING / KEGG / GO / DisGeNET / PubMed
│  (开放API·限速)     │
└───────────────────┘
        │
        ▼
┌───────────────────┐
│  核心分析模块       │  基因ID转换 → GO/KEGG富集分析 → PubMed文献批量抓取
└───────────────────┘
        │
        ▼
┌───────────────────┐
│  LLM 约束模块       │  固定提示词 · 仅基于抓取摘要总结 · 输出附带 PMID
└───────────────────┘
        │
        ▼
┌───────────────────┐
│  交互界面           │  Streamlit：CSV上传 / 结果预览 / 报告导出 / 可视化
└───────────────────┘
```

**模块说明**

1. **数据接口层**：调用 Entrez、STRING、KEGG 等开放公共 API，合规限速访问，无自有数据库、无版权风险。
2. **核心分析模块**：基因 ID 转换、GO/KEGG 富集分析、PubMed 文献批量抓取。
3. **LLM 约束模块**：采用固定提示词，要求模型仅基于抓取到的文献摘要进行总结，禁止生成原文以外结论，输出附带 PMID 溯源号。
4. **交互界面**：使用 Streamlit 搭建网页端，支持 CSV 文件上传、结果预览、报告导出。
5. **验证方案**：采用 TCGA 肺腺癌差异基因集作为测试集，对比人工文献调研结果，评估工具召回率与幻觉发生率。

## 🚀 快速开始

### 环境要求

- Python 3.9+
- 可访问 KEGG / GO / PubMed 等公共 API 的网络环境
- 一个大语言模型 API Key（用于 LLM 约束总结模块）

### 安装

```bash
git clone https://github.com/<your-username>/<your-repo-name>.git
cd <your-repo-name>

python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate

pip install -r requirements.txt
```

### 配置

在项目根目录创建 `.env` 文件（或按 `config.example` 配置）：

```env
# 大模型 API 配置（示例）
LLM_API_KEY=your_api_key_here
LLM_BASE_URL=https://your-llm-endpoint/v1
LLM_MODEL=your_model_name

# NCBI Entrez（建议填写，可提升限速额度）
NCBI_API_KEY=your_ncbi_key_here
NCBI_EMAIL=your_email@example.com
```

> 🔐 请勿将 `.env` 或任何密钥提交至仓库（已默认加入 `.gitignore`）。

### 启动

```bash
streamlit run app.py
```

浏览器打开终端提示的本地地址（通常为 `http://localhost:8501`），上传基因列表 CSV 即可开始分析。

### 输入格式

CSV 文件需包含一列基因标识（如基因 Symbol 或 Entrez ID），示例：

```csv
gene
TP53
EGFR
KRAS
MYC
...
```

### 📂 示例数据体验

为了快速验证流水线功能，项目根目录提供了一份包含 15 个肺癌相关基因的测试集 **`example_genes.csv`**。 
下载或克隆本项目后，直接将该文件上传至 Streamlit 网页界面，即可一键跑通“ID转换 → 功能富集 → 文献抓取 → LLM总结”的全流程。

### 人工交叉验证机制
为了确保自动化流程的准确性，本工具设计了一套严谨的人工对照验证机制。在系统输出最终结论后，支持导出中间结果（CSV）进行人工复核。验证重点在于比对大模型生成的摘要与 PubMed 原始摘要的核心信息是否一致，以及校验模型返回的 PMID 是否真实存在于本次抓取的文献集合中，确保每一条临床证据都有迹可循。

## 🧩 可拓展性

当前工具仅以肿瘤候选基因注释作为示范测试场景，整套系统采用**模块化架构**，并不绑定肿瘤研究方向。

- **横向拓展**：仅需更换后端富集数据库、修改检索关键词模板，即可拓展到植物生物学、微生物组、神经退行性疾病、代谢性疾病、病原微生物等场景，支持基因、蛋白、代谢物、菌群标记物等不同生物实体的文献证据挖掘与功能注释。
- **纵向泛化**：项目中「文献批量抓取 → 基于原文摘要约束大模型输出 → 结果附带文献溯源编号」的核心流水线具备独立泛化价值。剥离生物专属的 ID 转换与通路富集模块后，可改造为**通用科研文献梳理底座**，适配其他学科的文献调研需求（远期迭代方向）。

## 💡 创新点

1. **场景融合创新**：区别于单纯富集网站与无约束 AI 问答，将权威数据库检索、文献溯源、大模型总结绑定在同一条流水线，专门解决生信下游文献调研痛点。
2. **幻觉约束机制**：不依靠大模型自由推理，摘要素材全部来自 PubMed 公开摘要，每条结论自带文献编号，结果可复核。
3. **模块化解耦设计**：业务场景未硬编码锁定肿瘤方向，富集库、检索模板可灵活替换，为跨方向拓展预留架构基础。
4. **轻量化易上手**：部署门槛低，代码开源，面向本科生科研群体。

│   └── llm_summary.py      # LLM 受约束总结（PMID 绑定）

├── docs/                   # 使用手册、测试对比报告
└── README.md

### 模块化解耦说明
本项目在架构设计上严格遵循“高内聚、低耦合”原则。基因ID转换（`gene_convert`）、功能富集（`enrich`）、文献抓取（`pubmed_fetch`）与大模型总结（`llm_summarize`）等核心功能全部封装为独立模块。主程序（`app.py`）仅作为调用者，不包含具体业务逻辑。这种设计使得后续更换其他富集数据库（如更换为 Reactome）或切换其他大模型 API 时，无需改动核心流程代码，极大提升了系统的可拓展性。

### 接口连通性测试
项目根目录包含 `test_llm.py` 脚本，主要用于开发及部署阶段测试大模型接口（API）的连通性与鉴权状态。在正式运行主程序前，可先执行该脚本确认网络及密钥配置无误。

## ❓ FAQ

**Q：工具目前只验证了肿瘤场景，应用面会不会比较窄？**
A：肿瘤只是用于验证系统稳定性的测试场景，流水线本身没有写死肿瘤关键词。核心逻辑是「输入生物分子标识 → 自动查库 → 挖掘文献 → 结构化总结」，植物、微生物、代谢病等课题只需切换配套数据库和检索模板即可使用。全学科通用是远期设想，本次作品聚焦生信场景，优先保证结果可靠、可控，规避 AI 泛化带来的风险。

**Q：和市面上普通 AI 文献综述工具的差异在哪里？**
A：普通 AI 文献工具多为自由检索、自由总结，缺少生物数据库联动，也没有配套基因富集分析。本工具的特色是**生物分子富集分析 + 定向文献溯源深度绑定**，瞄准生信课题完成差异分析之后的文献调研这一细分痛点，而非泛泛的通用读文献工具。
